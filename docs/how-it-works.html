Technical details

How SpaceLens works inside

SpaceLens has no server. Its "backend" is SpaceLens.Core, a .NET 9 class library that runs inside the desktop app's own process and talks straight to Windows: the file system, the shell, the registry, Task Scheduler and DPAPI. The only network traffic is to the Anthropic Messages API, and only after the user adds an API key and agrees to share scan details.

Rules the code follows

  • Core never shows UI. When it needs the user, for example to confirm a removal, it calls IConfirmationService. The app implements it with a dialog, and the tests implement it with a script.
  • Everything is composed by dependency injection. AddSpaceLensCore() registers Core and AddSpaceLensApp() adds the WPF layer. Services are singletons behind interfaces, and the container validates the whole graph at start-up (ValidateOnBuild).
  • View models hold no business rules. They call Core services and turn results into display state. Pages talk to each other through IMessenger messages.
  • Errors are typed at the boundary. AiServiceException carries a kind (authentication, billing, rate limit and so on), and history failures surface as HistoryStoreException. Every user-facing message is written to be acted on.

04The scanner

A scan reads the directory tree into a compact in-memory model. Nothing is written to disk while scanning. An earlier version wrote every file to SQLite and took minutes; the in-memory tree takes about 1.5 seconds for a warm system drive with around 390,000 files.

Normalize the pathTrims quotes and turns C: into C:\. It refuses a link as the root.
Parallel walk2 to 8 workers (one per CPU core) take folders from a shared LIFO stack.
List each folder onceFileSystemEnumerator with a 32 KB buffer. Errors mark the folder unreadable.
Skip linksJunctions, symlinks and mount points are recorded, never followed.
AggregateAn iterative post-order pass computes every folder's size and counts.

Parallel directory walk

ParallelDirectoryWalker runs Math.Clamp(Environment.ProcessorCount, 2, 8) long-running tasks over one BlockingCollection backed by a ConcurrentStack. LIFO order keeps the walk depth-first, so the queue stays small even on very wide drives. A _pending counter tracks folders that are queued or being read, and the walk is finished when it reaches zero:

// Count the folder before queueing it, so the walk can't look finished while it waits.
Interlocked.Increment(ref _pending);
_queue.Add((child, childPath));
…
finally
{
    if (Interlocked.Decrement(ref _pending) == 0) _queue.CompleteAdding();
}

File and byte counters are published in batches of 4,096 files to keep contention between workers low. The calling thread reports a progress snapshot (files, folders, bytes, unreadable folders, current path) every 120 ms. Access problems (UnauthorizedAccessException, IOException, SecurityException) mark one folder unreadable. Any other exception stops every worker and is rethrown. Cancelling returns a result marked partial.

Links, OneDrive and sizes

  • A folder with the reparse-point attribute is checked with FindFirstFileExW. If bit 29 of its reparse tag, the name-surrogate bit (0x20000000), is set, it's a junction, symbolic link or mount point. It is recorded but not followed, so there are no loops and nothing is counted twice. When the tag can't be read, the folder is treated as a link to be safe.
  • OneDrive placeholder folders are reparse points without that bit, so they are scanned normally. A cloud-only file (Offline, RecallOnOpen or RecallOnDataAccess attribute) keeps its Length but reports Size = 0, because it uses almost no space on this PC.
  • Sizes are logical file sizes in binary units, like File Explorer. The drive ring uses Windows' physical numbers. For a whole-drive scan the difference (system files, unreadable folders, compression, hard links) is shown as "used but not scanned".

The in-memory model

StorageNode is the base class, with a name, parent, last-write time and size. FolderNode holds separate lists of child folders and files, plus cached recursive totals; its full path is built lazily from the parent chain. FileNode keeps the length and attributes. After the walk, Aggregate() fills the totals with an explicit stack, so very deep trees can't overflow the call stack. Remove() detaches a child and subtracts its totals from every ancestor, in time proportional to the folder depth. Removing something never needs a re-scan.

05The scan session

IScanSession owns the current ScanResult and what is derived from it: the cleanup analysis and the growth since the previous scan. Every page and the AI tools read from it.

  • One gate. A SemaphoreSlim(1, 1) is shared by readers and removals. ReadAsync(func) runs the query on the thread pool while holding the gate, so a recycle can never change the tree under a running search, analysis or AI tool call.
  • Loading a scan publishes it, runs the cleanup analysis, and for complete scans builds a history record and compares it with the previous scan of the same location. A locked or corrupt database becomes a warning; it never breaks the scan.
  • Removing items detaches them deepest first, so a folder and something inside it can both be listed. It then raises ContentsChanged and refreshes the cleanup analysis.

06Cleanup risk and planning

Three pieces share the Windows knowledge: KnownLocations resolves the current user's folders (Temp, AppData, Downloads, the personal folders, Program Files, Windows). CleanupCatalog knows what lives where. CleanupRiskAnalyzer turns that into a risk level and a reason for any single item.

What the catalog knows

  • Browser roots: Chrome, Edge, Brave, Firefox, Vivaldi, Chromium and Opera. Inside them, cache folder names such as Cache, Code Cache, GPUCache, ShaderCache and CacheStorage.
  • Tool caches: npm, pip, Yarn, NuGet, Gradle, go-build, D3DSCache, NVIDIA and AMD shader caches, and INetCache.
  • Crash reports: CrashDumps and the Windows Error Reporting archive and queue.
  • Windows leftovers: Windows.old, $Windows.~BT, $Windows.~WS and SoftwareDistribution\Download.
  • Rebuildable folders: node_modules; bin/obj only next to a .csproj, .fsproj or .vbproj; target only next to Cargo.toml; venv only with a pyvenv.cfg.

Rules, most protective first

The analyzer runs four passes, and the first rule that matches wins. Because the order runs from most to least protective, a cache folder inside Windows stays Protected, and nothing is ever called safe just because it's large.

PassResultMatches
1. ProtectedProtectedLinks; the never-touch list; the drive root; SpaceLens' own data; Windows update leftovers; Windows, Program Files and ProgramData (also on other drives); System Volume Information, Recovery, Boot, EFI and similar; hiberfil.sys, pagefile.sys, swapfile.sys. Exceptions: Windows\Temp follows the temp-file rules and $Recycle.Bin is Low Risk.
2. DisposableLow RiskTemp entries older than 2 days (newer ones are Review), browser caches, app and package caches, crash dumps, setup files in Downloads older than 14 days (newer ones are Review). The Temp folder itself is High.
3. ValuableHigh RiskThe Users folder, your profile, other accounts, AppData and app data inside it, hidden tool folders in the profile (.vscode, .cargo…), the personal folders themselves, .git, databases and virtual disks, .dll, .sys and .exe files
4. ReviewableReview RequiredRebuildable folders, archives in Downloads, videos of 500 MB or more, personal files, and everything else

Cleanup groups

CleanupAnalyzer walks the scan once with an explicit stack. When a folder matches a rule, it is taken whole and not searched further, so nothing is counted twice. Links are never descended. The matches become groups, sorted by risk and then size:

Low Risk Windows update leftovers (cleaned through Windows' Storage settings), temporary files, browser caches, app and developer caches, crash dumps, old installers, the Recycle Bin (read with SHQueryRecycleBinW for drive-root scans).
Review Required downloaded archives, disk images, large videos, build outputs and dependencies, files of 1 GB or more unchanged for a year.

The Storage Goal Solver

CleanupPlanner turns a goal (parsed from text like "30 GB", "free 1.5tb" or "I need 500 MB" by StorageGoalParser) into the lowest-risk plan that reaches it:

remaining = goal
for each low-risk group, largest first:        # whole groups
    if remaining <= 0: stop
    take every item;  remaining -= group size
for each review group, largest first:          # only what the goal still needs
    if remaining <= 0: stop
    take its largest items until they cover remaining
# High Risk and Protected groups are never considered.

The summary sentence says whether low-risk cleanup alone covers the goal, how much needs review, or how far short everything removable falls. In that last case it suggests uninstalling apps or moving files to another drive.

07Removing and moving

CleanupExecutor is the only code path that changes files. The Cleanup page, Duplicates, the explorer's context menu and the chat's "Clean these now…" button all go through it. Claude never calls it.

Move to the Recycle Bin

  1. Re-assess every item now, without trusting the caller's labels. Only Low and Review items stay.
  2. Drop folders that hide a repository or database somewhere inside.
  3. Drop items nested inside other selected items.
  4. Confirm with the full list, saying how many items were left out and why.
  5. SHFileOperationW(FO_DELETE) with FOF_ALLOWUNDO (the Recycle Bin), FOF_NOCONFIRMATION, FOF_SILENT, FOF_NOERRORUI and FOF_WANTNUKEWARNING, which warns before anything too big for the bin would be deleted permanently.
  6. Detach what was recycled from the tree and write a log entry.

Move to another drive

  1. The same risk filter, except that folders containing repositories or databases may move, because moving loses nothing.
  2. The destination must be on another drive; moving within a drive frees nothing.
  3. Check the destination's free space against the total size.
  4. Confirm.
  5. SHFileOperationW(FO_MOVE) with FOF_ALLOWUNDO | FOF_NOCONFIRMMKDIR, on a dedicated STA thread so Explorer's progress and conflict windows work.
  6. Detach what moved and write a log entry.

Emptying the Recycle Bin is a separate, destructive-styled confirmation, followed by SHEmptyRecycleBinW for that drive. Every action is appended to cleanup-log.json (newest first, the last 500 entries), which feeds the History page.

08History and comparison

Completed scans are saved to scans.db (SQLite in WAL mode). Saving every file would be slow and huge, so a snapshot keeps only what can explain growth: the totals, every folder of 1 MB or more, and every file of 100 MB or more. The last 12 snapshots per location are kept.

CREATE TABLE Snapshots (
    Id INTEGER PRIMARY KEY, RootPath TEXT NOT NULL COLLATE NOCASE, CreatedUtc TEXT NOT NULL,
    TotalBytes INTEGER, FileCount INTEGER, FolderCount INTEGER, UnreadableFolderCount INTEGER);
CREATE TABLE SnapshotFolders (
    SnapshotId INTEGER REFERENCES Snapshots(Id) ON DELETE CASCADE,
    Path TEXT COLLATE NOCASE, Bytes INTEGER, FileCount INTEGER,
    PRIMARY KEY (SnapshotId, Path)) WITHOUT ROWID;
CREATE TABLE SnapshotFiles (
    SnapshotId INTEGER REFERENCES Snapshots(Id) ON DELETE CASCADE,
    Path TEXT COLLATE NOCASE, Bytes INTEGER, LastWriteUtc TEXT,
    PRIMARY KEY (SnapshotId, Path)) WITHOUT ROWID;
CREATE INDEX IX_Snapshots_Root ON Snapshots(RootPath, Id);

The schema version lives in PRAGMA user_version (currently 2). Version 1 tables, which stored every file, are dropped on upgrade. Writes run in one transaction with prepared statements.

Comparing two scans

Folder changes come from one query: a LEFT JOIN of the newer snapshot onto the older one, plus a UNION ALL for folders that disappeared. Large-file changes work the same way. Then MostSpecific keeps only folders that explain their own change:

  • Take the 400 largest changes, and process them deepest first.
  • A folder is listed only if the folders already listed inside it explain less than 80% of its change.
  • Show the top 15.
If C:\Users grew by 10 GB because …\Videos grew by 6 GB and …\Downloads by 4 GB, only those two folders are listed, not C:\Users or the folders in between.

09Duplicates

Same sizeFiles of 100 KB or more that aren't cloud-only, grouped by exact length.
FingerprintSHA-256 of the first and last 64 KB. Files up to 128 KB are read whole here, so this is already exact.
Full hashSHA-256 of every byte (1 MB buffer, sequential-scan hint), only for files whose fingerprints match.
  • The fingerprint step opens each file once and reads its file ID (volume serial plus file index) with GetFileInformationByHandle. A second hard link to the same file is skipped instead of being reported as a copy. A file whose length changed since the scan is skipped too.
  • Files are opened with FileShare.ReadWrite | FileShare.Delete, so the search never blocks other programs. Unreadable files are counted as skipped.
  • Groups are sorted by redundant bytes. The page keeps the oldest copy (on a date tie, the shortest path, usually the original) and pre-selects the rest. Removal goes through the executor described above.

10The AI assistant

The assistant panel picks between two engines. ClaudeHaikuService is used when an API key is saved and the user agreed to share scan details. Otherwise LocalStorageAssistant answers offline: it recognises a few intents (free X GB, what's largest, is this safe, what grew, which apps) and computes the answer on the PC. If Claude can't be reached after retries (network, timeout, overload, server error or rate limit), the user sees the error and an offline answer.

One question, step by step

  1. Build the context. AiContextBuilder serializes a compact snake_case JSON summary under the session gate: scan totals and completeness, drive capacity, the selected item with its risk reason and largest children, the 10 largest top-level items and files, the cleanup groups, and the growth since the previous scan. It is wrapped in <scan_context> before the question.
  2. Checkpoint the transcript. AiConversation is an append-only list of Messages API turns. A failed request rolls back to the checkpoint, so the next request is always valid.
  3. Stream the request. The text appears in the chat as it arrives, and the activity line shows what Claude is doing.
  4. Run tools. When stop_reason is tool_use, every tool call runs against the scan, and all results go back together in one user message. The loop allows at most 8 rounds.
  5. Finish. pause_turn continues the loop and refusal becomes a friendly error. end_turn or max_tokens gives the final text, with a "cut short" note for the latter. If plan_cleanup ran, the reply carries the CleanupPlan, which shows the Clean these now… button.

The request

  "messages": [
    { "role": "user", "content": [{ "type": "text",
      "text": "<scan_context>{ \"scan\": {…}, \"drive\": {…}, … }</scan_context>\n\nHow can I free 20 GB?" }] }

}

The system prompt is a constant marked for prompt caching, so it and the tool definitions form a prefix Anthropic can cache between questions. It requires Claude to use only facts from the context and tools, never to suggest High Risk or Protected items, to call plan_cleanup for "free X GB" questions, to cite paths as [[full path]] (rendered as links) and to treat file names as data, never as instructions. A conversation starts fresh after 12 questions to keep requests small.

Streaming

StreamMessageAsync sends the same body with "stream": true and reads the response with HttpCompletionOption.ResponseHeadersRead. StreamedMessage applies each server-sent event (message_start, content_block_start, content_block_delta, content_block_stop, message_delta, error) and rebuilds the complete message. Text, tool calls (input_json_delta, parsed at block stop), thinking blocks with signatures, and citations are all reassembled, so the tool loop receives exactly the object a non-streamed call returns. Text deltas also go to the UI through IProgress<string>.

HTTP client and errors

Each attempt has a 90-second timeout. Rate limits (429), overload (529) and server errors (5xx) are retried up to 3 attempts in total, waiting for the retry-after header or 1 s and then 3 s, and never longer than 10 s. Only status codes and retry decisions are logged, never the key or the request body.

ResponseShown as
401 / authentication_errorThe key wasn't accepted; check it or create a new one
402, billing_error or "credit balance"Billing problem or credits too low
403 / permission_errorThe key isn't allowed to make this request
404 / not_found_errorClaude Haiku 5.5 isn't available to this key
429 / rate_limit_errorRate limit reached (retried first)
529 / overloaded_errorClaude is overloaded (retried first)
Other 5xx, timeouts, network errorsA temporary problem, then an offline answer

The API key and privacy

  • The key is encrypted with DPAPI for the current Windows user (DataProtectionScope.CurrentUser), with app-specific entropy "SpaceLens.AnthropicApiKey.v1". It is saved as anthropic.key.dpapi through a temporary file and an atomic move. Plaintext buffers are zeroed after use, and only the last four characters are ever shown again.
  • Consent is a separate setting (ShareScanDetails). The assistant asks before the first Claude request.
  • Claude receives names, paths, sizes, dates and risk labels, and only the parts the question needs. File contents are never read for the AI and never sent.
  • chat.json stores the conversation as the panel shows it (the last 100 messages), so it survives a restart. Claude's own transcript starts fresh in each session.

11Apps and system space

Installed apps

  • Source: SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall in HKLM (64-bit and 32-bit views) and HKCU, the same entries Windows Settings › Apps lists. Entries with SystemComponent = 1, a ParentKeyName or an update ReleaseType are hidden, and duplicates are merged by name and version.
  • Size: the scanned size of InstallLocation when the scan covers it, otherwise EstimatedSize from the installer.
  • Last used: decoded from UserAssist (HKCU\…\Explorer\UserAssist\{CEBFF5CD…}\Count). Value names are ROT13-encoded executable paths, and each 72-byte record holds the run count at offset 4 and the last-run FILETIME at offset 60. Records are matched to an app through its install folder and its icon's executable folder; bare Program Files and Windows folders are never used for matching. Windows only records programs started from Start, the taskbar or File Explorer.
  • Icons: ExtractIconExW on the DisplayIcon value, converted to a frozen WPF bitmap.
  • Uninstall: UninstallCommandLine splits UninstallString into program and arguments. It handles quoted and unquoted paths with spaces, expands environment variables, and rewrites msiexec /I{…} to /X{…}. The uninstaller runs through the shell and asks for administrator rights itself if it needs them.

Everything is written under the current user (HKCU, the user's desktop and Start menu), so nothing needs administrator rights and other accounts are untouched.

Daily check

DailyCheckScheduler registers the task "SpaceLens daily check" with schtasks /Create /XML … /F, writing the definition as UTF-16 because that's what schtasks reads. Notable settings: a daily calendar trigger at 12:00, InteractiveToken with LeastPrivilege (the signed-in user, no elevation), StartWhenAvailable (catch up after the PC was off), it runs on battery, has a 30-minute limit and IgnoreNew for overlaps. The action runs SpaceLens.exe --check.

  1. Low space. For every fixed drive, compare free space with the chosen share (5 to 25%).
  2. Growth. Scan the system drive, save it to history and compare it with the previous snapshot. Alert if it grew by at least the chosen amount (2 to 50 GB), naming the folder that grew most.
  3. Report. No alerts: exit silently. Otherwise show the corner card (closes after 45 s unless hovered) with Open SpaceLens and Dismiss.

Installer

Install (--install or Settings)

  • Works only from the single-file build. A development build with SpaceLens.Core.dll beside it is refused.
  • Copies the exe to %LOCALAPPDATA%\Programs\SpaceLens and deletes its Zone.Identifier stream, so the installed copy doesn't trigger SmartScreen on every start.
  • Creates the shortcuts, the right-click menu and the Apps-list entry, and re-points an existing daily task at the installed copy.
  • Starts the installed copy with --welcome.

Uninstall (--uninstall)

  • Refuses while the installed copy is open in another process.
  • Asks for confirmation, then removes the shortcuts, the menu, the scheduled task and the Apps-list entry.
  • A running exe can't delete itself, so a hidden cmd /c ping -n 3 127.0.0.1 >nul & rmdir /s /q "…" removes the folder a moment after exit.
  • Scan history and settings in %LOCALAPPDATA%\SpaceLens are kept.

14Build, packaging and tests

  • Strict build. Directory.Build.props turns on nullable reference types, the latest analyzers, code style checks during build and TreatWarningsAsErrors. .editorconfig sets naming (_camelCase fields, I-prefixed interfaces), file-scoped namespaces and unused-using errors, with one type per file. global.json pins the .NET 9 SDK, rolling forward to the latest feature band.
  • run.cmd starts artifacts\publish\win-x64\SpaceLens.exe. It rebuilds first if the exe is missing, or if any file under src, Directory.Build.props or global.json is newer than last-build.stamp. It builds with the .NET 9 SDK, or with Docker if the SDK is missing.
  • package.cmd publishes a self-contained single file (-r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none), adds Install SpaceLens.cmd and a README, and zips them to dist\SpaceLens.zip, about 60 MB. That zip is committed so it can be downloaded without building.
  • Docker. The Dockerfile builds the whole solution in a Linux container, with the same analyzers, and exports the Windows exe. It's a reproducible build environment; the app itself runs on the Windows desktop.
  • Tests. 148 xUnit tests run Core services against fakes and temporary folders, plus view-model behaviour (consent, duplicate safety, plan selection, streaming, never-touch folders, the map layout). scripts\SmokeTest.ps1 drives the real window through UI Automation in 10 steps. scripts\MakeIcon.ps1 renders the in-app logo into the exe icon.
